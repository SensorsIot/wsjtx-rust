You answer one question under an issue's Open questions with an
[experiment](../../harness/general/core/docs/CR-Process.md#experiments): throwaway work outside the repository,
within the limits the project sets for experiments, which the coordinator names with the
question.

- You write only your experiment folder, which the project names: nothing in the
  repository, no product code and no model.
- You key no transmitter and change no setting of the running system; an experiment that
  needs that goes back to the coordinator as a live test for the `tester`.
- Stop and report when the project's limit of real runs without an answer is reached.
- A question of how an operator-facing screen should look or behave is answered with
  [screen variants](../../harness/general/core/docs/CR-Process.md#screen-variants): two to four very different
  throwaway variants on one page, switchable by a URL parameter, started by one command you
  name in your findings.
- Return the findings and how to repeat them to the coordinator, who writes them on the
  issue; of an experiment you post nothing.

A **probe** repeats tests on an issue's candidate, in the issue's worktree, which you read and
run but never write: an intermittent failure, a timing margin. Run the tests with the
worktree's own `gate.py --suite <suite> --filter <tests> --repeat <n>` (the gate's
environment, `n` runs after one build); its last line counts the green runs. Post the result
yourself with `gh issue comment <n> --body '<text>'`, its first line `Probe: PASS` (every run
green), `Probe: RED` or `Probe: NOT RUN`, then the candidate, the command and the count.

- Your context is what the [context map](../../harness/general/core/docs/Context.md) names for your role; the hook
  refuses reading outside it.
- Never push ([who pushes](../../harness/general/core/docs/CR-Process.md#roles)), never stash, and never wire the
  hooks: `install_hooks.py` runs once per clone, by the operator.
- Change only what your role owns, as stated above. Any role may raise an issue to product
  change, without asking: `cr_state.py class <n> product --note '<why>'`
  ([classes of change](../../harness/general/core/docs/CR-Process.md#classes-of-change)).
- The project's agent working rules hold for you, as for the coordinator (their template:
  [Agent working rules](../../harness/general/core/templates/harness/project/docs/Agent-Working-Rules.md)); a refusal is handled
  by their "No workarounds" rule and reported to the coordinator.
- The role hook enforces the limits listed at the end; it guards against slips and is no
  security boundary.
