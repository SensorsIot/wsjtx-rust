## Human-readable architecture and data model

Catalogue **items** describe variables, codecs, formats, exchanges, operations, events, families and devices. Runtime **parts** are Application, StandardInterface, PC and Transceiver. The sole `radioControl` usage contains one PC and one radio. PC.application exchanges typed requests/results/events with PC.standardInterface, which delegates CAT to the radio. In this project that must refine the existing **station-controller to radio** path within User / Viewer / Station Controller / Radio. It must not create a fifth box, replace the browser/server split or settle browser placement.

The catalogue, selected station configuration, our implemented capabilities and observed state require distinct ownership. A catalogue item is not execution authority. #8 owns one shared catalogue/CAT adapters; #6/#7 own common receive identity/samples/jobs/preprocessing; #9 owns transmit authority and independent halt. Audio and CAT remain independently selected and available.

Cardinalities below are literal input declarations: `[0..1]` optional, `[1]` singular, `[*]`/`[0..*]`/`[1..*]` collections. Omitted multiplicities and inherited effective types are not resolved by this scanner. Unbounded multiplicity is not a runtime memory budget.

### Runtime payload interpretation

- `SemanticValue` carries definition/kind plus optional scalar/text/bytes/record fields. Exactly-one representation is prose, not an asserted integrity rule. Runtime values must match the definition and device domain; strings listing values are not Rust types.
- `CommandInvocation` carries operation and arguments. `OperationResult` distinguishes outcome and freshness/age, with readback/value-match flags. `StateEvent` identifies origin/time; `ReceivedMessage` keeps format, role, optional invocation relation, raw frame and decoded values. Echo cannot confirm an operation.
- `ConnectionConfiguration` proposes transport/endpoint, addresses, baud/echo/notifications, serial framing, timeouts/retries and one pending query. The instantiated session assumes USB serial, example 94/E0 addresses, 8N1/no handshake, 1000 ms and three retries (L398-417). Baud is not bound. These are not inspected target settings. DTR/RTS opening behavior and USB SEND/keying mappings remain unknown.
- Missing runtime decisions: existing station authority/context, radio ownership, connection/operation generation, monotonic observation time/deadline, cancellation and indeterminate-write outcomes, bounded payload/queue retention and release ownership. Cache age needs a source/clock contract; ACK is not a fresh measurement.

## Operations, exchanges and execution flows

Operations are semantic behaviors, with an explicitly unordered `commands[0..*]` reference set (L147-168). Cache/local operations may use zero wire commands; one semantic operation may use several exchanges. Each command references a request format and exchange rule; formats can share ACK/NAK/data roles. A message is an instance, not a command definition. Preserve this distinction without executing arbitrary catalogue strings.

## Material source findings and adoption limits

**PREAMP:** original variable retains dB (L721-731), while support supplies selectors 0/1/2 (L2470-2476) and finding recommends selectors. Preserve the original claim in transcription but use a unitless selector plus separately verified gain in an adopted design. Sources: [include/hamlib/rig.h:1122](https://github.com/Hamlib/Hamlib/blob/075b78cb0560e892c81bc73890d633cc11f23f59/include/hamlib/rig.h#L1122); [rigs/icom/ic7300.c:1038](https://github.com/Hamlib/Hamlib/blob/075b78cb0560e892c81bc73890d633cc11f23f59/rigs/icom/ic7300.c#L1038); [rigs/icom/level_gran_icom.h:18](https://github.com/Hamlib/Hamlib/blob/075b78cb0560e892c81bc73890d633cc11f23f59/rigs/icom/level_gran_icom.h#L18).

**OVF:** original variable/support are readWrite (L2058-2070, L3026-3031). Header describes read overflow; get handler has the case; set handler has no OVF case and rejects unsupported functions. A mask-derived write claim must not enable a setter. Sources: [include/hamlib/rig.h:1376](https://github.com/Hamlib/Hamlib/blob/075b78cb0560e892c81bc73890d633cc11f23f59/include/hamlib/rig.h#L1376); [rigs/icom/icom.c:7558](https://github.com/Hamlib/Hamlib/blob/075b78cb0560e892c81bc73890d633cc11f23f59/rigs/icom/icom.c#L7558); [rigs/icom/icom.c:7303](https://github.com/Hamlib/Hamlib/blob/075b78cb0560e892c81bc73890d633cc11f23f59/rigs/icom/icom.c#L7303).

**Types/domains:** generic frequency is Real/freq_t; initial IC-7300 may use integer Hz but other radios/fractional steps require a separate representation decision. Zero quantum conflates unknown and continuous granularity. Normalized BCD needs finite/range/rounding/boundary checks. AGC times are mode-dependent discrete codebooks, not every value in 0..8 seconds. Calibration endpoints do not establish hard extrapolation limits or TX permission.

**Coverage:** 59 bindings include metadata slots, not 59 fully mapped commands. Direct mappings cover frequency, PTT and 13 levels. Mode/filter/DATA have backend references without direct formats in this input. Static masks/status are not our implementation, qualified firmware or runtime evidence. Catalogues/configuration also lack complete revision, licence, per-field confidence and stable-ID migration semantics.

**Scope:** catalogue knowledge must not enable raw CAT. TX band/PTT/VOX/tuner/Morse/voice-memory knowledge is not runtime permission; #9 owns TX/halt. Initial runtime scope remains required receive queries, with writes conditional on contract approval. No duplicate audio jobs, resampler, FFT, profiles or authentication belong here.
